# M6 live-backend dashboard acceptance

The kickoff's M6 check asks for an authenticated browser/Electron dashboard
with hosts, VMs, activity, terminal and console, proven with Playwright and
screenshots. The default `npm run smoke` suite runs against the in-browser
stand-in API (`ui/src/api/standin.ts`). This suite runs the **production
`ui/dist` against a real `arxd`**, so it proves the backend and the UI together.

## Run it

From the repository root, with the scratch variables from
[dev-scratch.md](dev-scratch.md) set (`TMP`, `TEMP`, `CARGO_TARGET_DIR`,
`npm_config_cache`, `PLAYWRIGHT_BROWSERS_PATH`):

```sh
npm ci
npx playwright install --only-shell chromium   # once
npm run build                                  # production ui/dist
cargo test -p arxd --test dashboard_live --no-run   # optional: pre-build the launcher
npx playwright test --config ui/tests/live/playwright.live.config.ts
```

Screenshots land in `test-results/m6-live-screenshots/` (`01-login.png` …
`11-session-ended.png`, overwritten on every run; override with
`ARX_LIVE_SHOTS`). Traces and failures go to `test-results/m6-live/`. Both
folders are gitignored. The screenshots show the real machine's host name,
OS, CPU and memory, so review them before you attach them anywhere public.

Optional variables: `ARX_LIVE_PORT` (default `47613`) and `ARX_LIVE_ROOT`
(default `$TMP/arx-live-dashboard`, the parent of the private state roots).

## What the fixture does

`ui/tests/live/playwright.live.config.ts` starts the ignored Rust test
`live_dashboard_server` in `crates/arxd/tests/dashboard_live.rs` as
Playwright's web server. The launcher:

1. creates a private state root (0700, or a TokenUser-owned protected DACL on
   Windows) under `ARX_LIVE_ROOT` and removes roots that earlier runs left
   behind under that root;
2. seeds 27 `run_command` activity rows through the public `Activity` store,
   and a VM catalog opened by the real `VmController` with two test VMs
   (one running Ubuntu with a ready snapshot, one stopped Windows);
3. provisions a synthetic per-run owner password through the real
   `arxd dashboard-password --state-dir` CLI on standard input. Production
   Argon2id parameters apply; the code has no cheaper test setting outside
   unit tests. The password is generated by the Playwright config, passed
   only through the environment and never printed;
4. runs the real foreground `arxd --config` with only `dashboard.listen` on
   `127.0.0.1`, `dashboard.dist` pointing at the built `ui/dist` and
   `dashboard.vm_state` at the seeded catalog, and waits until Playwright stops
   the process tree.

The non-ignored `live_fixture_seeds_activity_and_vm_catalog` test runs in the
normal nextest job and fails if the seeding drifts from the current schema.

## What it proves

| Area | Live assertion |
| --- | --- |
| Login | Production bundle (no demo banner), `401` before sign-in, server refusal message for a wrong password, sign-in sets `__Host-arx_session` as `HttpOnly; Secure; SameSite=Strict; Path=/` |
| Hosts | List shows the one local host as online; detail shows the two catalog VMs and recent activity |
| VMs | Table rows and states from the catalog; detail with size and the ready snapshot |
| Activity | 20 rows on page 1, 7 on page 2 through the server's `before_id` cursor, back to page 1 |
| Terminal | No owner executor is configured, so the ticket request answers 503 and the UI shows the documented unavailable state (error, Reconnect, input disabled) |
| Console | Production capture is unwired, so the ticket request answers 503 and the UI shows the documented unavailable state with no frame |
| Sign-out | `DELETE /api/v1/session` revokes the session: the UI reports "You are signed out." and `GET /api/v1/session` answers 401 |
| Session ended elsewhere | Sign-out in a second tab revokes the shared session; the first tab's next request gets 401 and returns to login with "Your session has ended." |

Measured on the Windows dev host (2026-11-23): 8 tests in 23–29 s with a
warm launcher build, stable over three consecutive runs; a cold launcher
build added about 80 s.

## What it does not prove

- **Terminal command execution.** A real run needs the Windows foreground
  owner executor (`execution` with a `local` endpoint, ADR 0029
  `current_user`) and a discovered tool cache, which this cross-platform
  fixture does not configure. Command admission, output bounds and exit are
  covered by the Rust dashboard stream tests and the stand-in Playwright
  suite.
- **The 4401 stream close.** No stream can open without a terminal or console
  backend, so revocation is proven here through the 401 path only. The 4401
  close of open streams is covered by the Rust session and stream tests and
  by the HTTP adapter's Vitest tests (`ui/src/api/http.test.ts`).
- **Electron against a live server.** The desktop shell answers every
  `/api/*` request with 503 until host connection is designed (see
  "Desktop" in [dashboard-api.md](dashboard-api.md)), so it cannot point at
  this server. `npm run test:desktop` still covers the shell itself.
- **Unverified on real hardware:** deployed HTTPS with owner certificates
  (`dashboard.tls`), the native console capture source, and VM rows written
  by a real VM runtime rather than seeded catalog rows.

## CI

The suite is not part of CI. The UI job does not build Rust, and building the
launcher there (about 80 s cold) or adding Node and Playwright to the Rust job
would exceed the roughly 30 s the CI time budget allows. Run it as a manual
acceptance command before an M6 sign-off or after dashboard backend changes.
