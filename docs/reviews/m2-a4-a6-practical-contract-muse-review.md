## Primary-source verification (read-only web; inference labelled)

- `KillMode=mixed`: verified against primary [systemd.kill](https://www.freedesktop.org/software/systemd/man/latest/systemd.kill.html#KillMode=): `mixed` sends SIGTERM to the main process and subsequent SIGKILL to **all remaining processes** of the unit's control group. Proposal's statement matches. Implication used in review: an ordinary killable helper that is still a member of the unit at main-exit is itself a kill target — this is why crash-provenance via SIGKILLing MainPID is fragile, not why cleanup is unnecessary.
- `ExitType=main` default: verified against primary `systemd.service` documentation (default `main` — manager considers the unit stopped when the main process exits; `Restart=no` suppresses restart, not teardown). Proposal's sentence ("treats MainPID exit as completion; Restart=no suppresses restart, not teardown") matches. Directory-removal at stop is **not** established by either directive — correctly left to A9/U9.
- Kernel cgroup v2: verified against primary [Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html): `cgroup.kill` recursively SIGKILLs descendants; `populated` tracks live tasks; childless taskless cgroups are removable including with zombies; freezing does not prevent fatal signals or empty-directory removal. Proposal's kernel-semantics paragraph matches. Its corollary also stands: frozen/sleeping helpers and held directory FDs are not a sound nonremovability induction — proposal correctly rejects them for A6.
- Inference vs. observation: everything above is document semantics. No installed-version teardown/removal behavior, no actual-host crash residue, and no scheduler/migration race outcome was observed in this review (no builds, tests, processes, or hosts touched). Any claim about what the disposable host **will** preserve must await the authorized bounded run.

## Spec axis — CONDITIONAL PASS (narrow amendment only, with required corrections)

The reduction is real and must stay labelled as a reduction: original Stage F A4 required a **crash-survivor** (prior instance's MainPID SIGKILLed → next instance observes the same live populated residue → S7 kills it). The proposal replaces provenance with a **present-residue mechanism check** (fixture-preseeded bounded populated leaf → production setup S7 kills/removes/verifies before Ready). Original A6 invited a native nonremovable leaf; the proposal replaces induction with **injected-port failures** through the real setup/readiness/persistence path.

This preserves the product security intent **if and only if** the amendment is accepted exactly as worded (A4 excludes crash lifecycle and directory-removal conclusions; A6 claims no native nonremovability; A9/U9 stays independently required) and the corrections below are applied before any source work. Rationale: the Arxcovo fence is "if residue is present at startup, it is killed, confirmed empty, removed, and verified before any execution admission; any janitor failure quarantines until restart." Crash provenance (whether `mixed` + `Restart=no` leaves a live leaf) and native nonremovability are platform/fault properties, not properties of Arxcovo code; conflating them makes acceptance flaky without strengthening the fence. The proposal's separation (native mechanism proof for A4 + deterministic failure-path proof for A6 + retained U9/A9) tests each product claim by the sound means and leaves the platform question open. That is proportionate, not a silent waiver — **provided** no future record cites this A4 as crash-lifecycle evidence or this A6 as kernel-nonremovability evidence, and M2 stays open.

## Security axis — ACCEPTABLE with five binding corrections (no optional framework)

A4 helper as proposed (test-only, fixed waiting code, prewritten memory 64 MiB / swap 0 / pids 1, blocked handshake before migration, parent-held identity, 15 s absolute lifetime, one `setup()` call, 5 s kill deadline, SIGKILL-death proof with reap, only S7 kills on success) is the right shape. Before implementation the amendment must additionally bind these points (minimal, no new harness):

1. **Helper provenance and passivity.** Helper is a fixed test-only re-entry (E4-fake pattern: re-entered test executable selecting one waiting behaviour), never a shell/command path; takes no commands, forks nothing (pids.max=1 would already fault a fork), opens no network/storage, runs no probes. Fixture seeds controller files (`memory.max=64 MiB`, `memory.swap.max=0`, `pids.max=1`) **before** placing the helper there — labelled explicitly as a fixture exception, not production setup.
2. **Single-kill attribution on the success path.** Only S7's `runs/cgroup.kill` write may kill on the accept path. The seeder places and migrates the helper but never writes `cgroup.kill`; owned failure-path cleanup kills only on the already-failed branch with a distinct label. Expiry or early helper death fails acceptance (no credit for an already-empty leaf).
3. **Reap ownership and identity.** The spawning parent survives through S7, holds the child handle, `waitpid`s it after setup, and asserts death by SIGKILL; the helper's leaf membership, aliveness, `runs` populated=1, empty `runs` procs, and sole MainPID-in-supervisor are all confirmed **before** the single setup call with >6 s of helper lifetime remaining (15 s lifetime minus 5 s deadline plus margin), so the deadline race is honest.
4. **No-adoption exclusivity.** Exclusively create `runs/` (`mkdir_runs == Created`, never adopt) and the literal `arx-0-0`; hold trusted no-follow descriptors from the A5 seeder pattern; reject links, foreign/replaced objects, and nested/unknown leaves; keep 4096-byte reads, 512-record/64-child listings, 1 MiB capture. Require `Ready(SetupEvidence { leaves_removed: 1, runs_created: false, unit_written: true, runs_written: true })`, literal leaf absence, fresh S9, runs reuse, and both controller writes.
5. **A6 join, not components.** A6 must drive **actual production setup** over the injected port (Busy at the validated leaf rmdir; populated held past 5 s; fresh post-rmdir verify residue) end to end through readiness latch → executor refusal with zero runner calls → persisted quarantined activity → no same-domain recovery on subsequent requests, with shutdown-Stopping preserved. Existing `h5_removal_busy`/`t15` unit pieces do not satisfy this alone. Mutations must catch swallowed rmdir failure, skipped verification, and early Ready; native A4 must reject an omitted kill.

Non-goals confirmed out of scope: no chmod/mount/migration-race/uninterruptible-task tricks, no unsafe survivor workload, no general restart infrastructure, no second setup as substitute, no manual pre-removal, no new selector API.
