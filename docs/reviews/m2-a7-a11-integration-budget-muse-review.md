## Spec - CONDITIONAL GO (proposal is the right minimal shape; two wording/bound pins block source prep)

The proposal correctly carries the brief: keep packaged `TimeoutStartSec=30s` and every hardening byte unchanged; send READY after one production setup plus all preflight admission (setup readiness, not acceptance); complete the existing MainPID/exe/supervisor identity-ack before ANY Runner child; run exactly two scoped workers, one owned account/Runner domain each, each sequential production arxd probe then fixed E4 reentry; parallel cases so sequential budgets do not sum; no generic executor or product concurrency change; parent cancels owned caller/shutdown tokens on failure/panic and joins BOTH workers before exit; fail-closed cleanup/residue/markers; driver accepts only both complete case oracles plus exact summary, service exit, and final cleanup, never early READY/ACK alone. Budget pins (55/10, 4096, 64MiB/swap0/pids32, package 30, monitor 120, Runtime 140, build 360, workflow 10min) are the minimal proportionate fence set, not a 100-line planning loop.

Feasibility against the callgraph is confirmed. `sudo_nnp.rs` currently asserts `cases == 2` then sends READY and holds ack after four sequential 20s `run_phased` calls (aggregate 80s pre-READY). The probe loop covers 9 TOOLS with a 5s per-version deadline plus a 5s rights deadline, i.e. a 50s documented worst case that exceeds a single 20s RunSpec. Moving the four calls post-READY/post-ACK moves them out from under the 30s startup window into the 120s monitor and 140s RuntimeMaxSec window. Parallel per-case worst cases do not sum. `RunSpec.timeout` admits up to 3600s, so 55/10 are admissible fixture values. Per-case arithmetic closes on paper: 3 property queries at 5s each (15) + 55 probe + 10 reentry + bounded cleanup allowance + join margin fits target per-case 90, ack 5, completion margin 10, inside monitor 120.

Blocking pins (source prep must include both verbatim; no new ADR):

1. Start-mode wording. The proposal says "blocking systemctl start returns READY". The driver uses `start --no-block` plus a `monitor_a1a2` poll loop (120s deadline, 5s `unit_properties` calls, local `verify_runtime` reads). State exactly: `--no-block` start, then monitor poll observes active, verifies runtime, checks MainPID/exe/cgroup membership, writes `identity-ack`, then observes inactive/failed with success result and exact libtest summary. The TimeoutStartSec argument still holds: READY is sent before the long work, so the 30s manager startup deadline is already satisfied when workers start.
2. Runner cleanup bound. The per-case 90 relies on "Runner cleanup retains its existing bounded allowance", but no explicit Duration bound was inspected in `exec/mod.rs` (residue is a monotone flag). The source slice must state the exact cleanup allowance in seconds, assert or measure each Runner cleanup inside it, and refuse on excess. The 90 target is then 15 admission + 55 probe + 10 reentry + stated cleanup allowance, with the remainder as explicit margin. If measurement shows the allowance exceeds the remainder, adjust only the two RunSpec values to exact finite replacements (for example 60/15) with the same derivation, not a generic NOGO.

Practicality notes (not blockers): 55 covers the 50s worst-case probe plus 5s Runner overhead; tight is acceptable because the oracle is fail-closed (excess refuses, never passes). 10 covers the 5s rights probe plus 5s overhead for the same reason. ACK 5 holds because the ack path is one 5s `unit_properties` call plus local bounded reads. Dynamic OS primitive blocking (thread spawn, scheduler delay) stays an existing limitation with no native guarantee claimed.
