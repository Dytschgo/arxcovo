## Security — CONDITIONAL PASS: one required pre-dispatch correction (C1), otherwise no findings

C1 (must fix before any D7i dispatch; not a safety hole, fail-closed): `driver.a7_alias_c2` compares **entire** `os.stat_result` objects — `before == after` across `readlinkat`, `os.stat('sudo',…) == info` across the digest read, and `os.stat('bin',…) == os.fstat(usrbin)`. `stat_result` equality includes `st_atime`/`st_atime_ns`, and both `readlinkat(2)` and `read(2)` mark atime for update (subject to `relatime`, the GitHub-runner default). On a fresh host whose `/bin` atime predates the run by >24 h or is older than its mtime, the first `readlinkat` advances atime and the check deterministically misfires to `E_ALIAS`; the same applies to the C2 recheck after the 282 KB digest read on `strictatime` or stale-atime mounts. The Rust side already excludes atime (`snapshot()`/`read()` carry dev/ino/mode/uid/gid/nlink/size/mtime/ctime only), and the comparator `_snapshot` likewise excludes it — the driver is the sole outlier. Impact is availability-only (refusal, never qualification), but on a no-retry one-shot grant a spurious refusal consumes D7i with zero native evidence. Existing mocks cannot see it (the alias test reuses one shared `SimpleNamespace` for before/after, so equality is trivially true).

Smallest fix (test-compatible except noted mock additions): add a `_stable_stat` helper mirroring the comparator snapshot (mode, uid, gid, ino, dev, nlink, size, `st_mtime_ns`, `st_ctime_ns` — atime excluded) and use it in the three comparisons; extend the alias-test `link`/`c2` namespaces with the missing fields and add an atime-only-difference positive case (must admit) so the regression is pinned. The `execution_admission_mutants`/`RuntimeAdmission` suites otherwise cover the fix unchanged (they patch whole functions). After the fix, publication review need only verify the small delta plus a rerun of the existing suites — no full re-review.
