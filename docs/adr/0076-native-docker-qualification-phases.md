# 0076 Native Docker qualification phases

Status: proposed (2026-11-27). Extends [ADR 0075](0075-authenticate-docker-receiver-capture.md).

## Decision

The owner-local Windows x64 qualifier can run the public receiver fixture,
restricted Compose installer, detached verification and installed HTTPS
endpoint. The signed receiver request carries the attributed fixture port
for the LAN inbound case. Each boot uses a disposable pair entered under
the run's charge journal. The installer uses the held stock helper to create a blank disk.
Detached and endpoint boots each copy the installer output while the source
pair is held without write sharing. The patched bundle uses the same paired
firmware bytes as the stock installer.

The Docker dossier binds the selected same-boot M4 TEST seal in its measured
dependencies. Inherited stages cite that seal explicitly. Their original
measurements and timestamps stay in the TEST dossier. The verifier checks
the same seal in each inherited row against the profile supplied at
selection. The Docker phases supply their own checked process, QMP, serial,
network and release observations. Earlier Docker dossiers without the M4
seal binding require a fresh qualification.

The fixture's route watch must stay current through paused checks, receiver
arming and QMP dispatch. During the intentional drift trial, the patched
backend and enrolled independent observer test the change. The qualifier
continues to check reserves and child custody. Only a validated signed
capture, a retired watch and settled fixture allow a replacement watch.
The replacement must see the original enrolled topology and stays armed
through the remaining phases and marker publication.

The static runtime stays behind its admission fence until native lifecycle,
private routing and opt-in publication can use the verified boot. The
qualifier's temporary workspace grants no authority over static VM media
or backups.

## Verification

The collector tests exercise the sealed reader, paired copies, Windows
loopback TLS, receiver signatures and refusal paths using fixtures. Native
VM boot, Docker, public-only networking, Windows custody, persistence and
live Cloudflare publishing are **unverified on real hardware**.
